## 3. Daftar Bug

Skala severity: **CRITICAL** = mematikan fungsi inti/risiko data · **HIGH** = fitur utama tidak berfungsi · **MEDIUM** = fungsi salah semantik/pesan/error-handling · **LOW** = kosmetik/infra.

### CRITICAL

**QA-01 — Registrasi/onboarding tenant gagal di bawah role non-superuser (RLS)**
- **Repro:** jalankan API dengan role `NOSUPERUSER NOBYPASSRLS` → `POST /api/v1/auth/register` dengan `tenant_name` terisi → **500** `"could not provision chart of accounts"`; log Postgres: `ERROR: new row violates row-level security policy for table "accounts"` pada INSERT seed COA.
- **Akar masalah:** transaksi Register (`backend/internal/auth/auth.go` baris ~104–120) membuat tenant lalu memanggil `SeedDefaultCOA` **tanpa** `set_config('app.tenant_id', …)` dalam transaksi tersebut, sehingga WITH CHECK policy RLS menolak.
- **Dampak:** registrasi tenant baru mustahil pada target arsitektur RLS (Phase C); saat ini hanya "berfungsi" karena role prod BYPASSRLS. Juga berlaku untuk `tenant.CreateAdditional`.
- **Saran:** bungkus proses seed dengan GUC tenant baru (atau eksepsi security-definer) sebelum C2 cutover.

### HIGH

**QA-02 — Rate limiter auth terlalu agresif & menyamarkan sinyal keamanan**
- **Konfigurasi:** `middleware.NewRateLimiter(5, time.Minute)` dipakai bersama oleh `/auth/login`, `/auth/register`, `/auth/refresh`, dan ketiga `/auth/2fa/*` (per IP).
- **Repro:** 5 permintaan auth apa pun dalam 60 detik → semua permintaan auth berikutnya **429**, termasuk login pertama pengguna sah; login password-salah yang seharusnya 401 ikut menjadi 429.
- **Dampak:** lockout pengguna sah (refresh token otomatis frontend ikut memakan jatah), office/NAT berbagi IP saling mengunci; sinyal brute-force (401) tertutup 429.
- **Saran:** pisahkan bucket per-endpoint, naikkan limit login, kecualikan refresh sukses dari hitung, pertimbangkan key per-IP+email.

**QA-03 — Pembuatan Delivery Order selalu gagal: "conn busy" pada FIFO costing**
- **Repro:** GRN masuk stok (qty 50) → `POST /delivery-orders` qty 10 → **500**; log: `costing: ResolveCOGS layer update: conn busy`. Deterministik (3/3 gagal).
- **Akar masalah:** `consumeFIFO` (`backend/internal/costing/costing.go` baris ~195–227) menjalankan `tx.Exec` **di dalam loop iterasi `rows`** dari `tx.Query` pada koneksi/transaksi yang sama — pgx v5 melarang operasi konkuren pada satu koneksi.
- **Dampak:** fitur DO (inti siklus penjualan barang berstok) mati total; COGS tidak pernah terposting.
- **Saran:** materialisasikan layer ke slice, tutup rows, baru jalankan UPDATE; tambah regression test integrasi GRN→DO.

**QA-04 — Pembuatan Supplier rusak untuk nilai default (NULL-scan)**
- **Repro:** `POST /suppliers` tanpa satu saja kolom opsional (`npwp`, `contact_person`, `payment_term_id`, `credit_limit_cents`, dst.) → **400** dengan pesan mentah `can't scan into dest[N] (col: X): cannot scan NULL into *string/*int64`. Hanya berhasil bila SEMUA field terisi dan `credit_limit_cents > 0` (nilai 0 tetap di-insert NULL).
- **Dampak:** master supplier praktis tidak bisa dibuat dari form normal; raw SQL bocor ke client.
- **Saran:** gunakan pointer/sql.Null* untuk kolom nullable + COALESCE nilai default.

**QA-05 — Quotation create 500 bila `payment_term_id` tidak dikirim**
- **Repro:** `POST /quotations` payload valid tanpa `payment_term_id` → **500**; log: `cannot scan NULL into *int64 (col: payment_term_id)`. Dengan field terisi → 201 normal.
- **Dampak:** SQ adalah langkah pertama funnel penjualan; API consumer/frontend versi lama langsung kena.
- **Saran:** scan ke `sql.NullInt64`/pointer pada re-read quotation.

**QA-06 — Pelunasan bertahap invoice & bill rusak (unique intent collision)**
- **Repro Sales:** `POST /invoices/{id}/payments` #1 → 201; pembayaran #2 (jumlah apa pun) → **409** `duplicate key value violates unique constraint "journal_entries_intent_unique" (SQLSTATE 23505)` — source_ref jurnal kedua bentrok (`PMT-{id}` statis per invoice). **Supplier:** pembayaran kedua → 409 `DUPLICATE_PAYMENT "payment already exists"` (salah pesan; bukan duplikat).
- **Dampak:** cicilan/pelunasan multi-termin — aliran kas paling umum di dunia nyata — tidak berfungsi; raw SQLSTATE bocor.
- **Saran:** nomor pembayaran global/per-invoice counter unik untuk source_ref; klasifikasikan unique-violation dengan pesan benar.

### MEDIUM

**QA-07 — Double-reverse jurnal VOID → 500.** `POST /journal-entries/{VOID}/reverse` kedua kali → 500 `JOURNAL_POST_FAILED`. Data aman (rollback bersih, diverifikasi SQL). Harusnya 409 bisnis.

**QA-08 — Tanggal di luar periode terbuka dilaporkan sebagai "ACCOUNT_NOT_FOUND".** `errorFor()` (`cash/helpers.go`) memetakan semua `ErrNoRows` → 404 ACCOUNT_NOT_FOUND, termasuk hasil kosong pencarian period. Repro: cash-in `entry_date=2025-01-01` (periode mulai 2026) → 404 pesan salah. Harusnya 422 `ENTRY_DATE_OUTSIDE_OPEN_PERIOD`.

**QA-09 — `/periods/close` tanpa header Idempotency-Key → 400 raw SQL leak.** Pesan: `invalid input syntax for type uuid: "" (SQLSTATE 22P02)`. Helper `idempotencyKey()` sudah ada di package period sendiri tapi tidak dipanggil di handler Close.

**QA-10 — `account_type` tidak divalidasi.** `POST /accounts` dengan `account_type:"NOT_A_TYPE"` → **201** tersimpan. Merusak pengelompokan laporan berbasis account_type. Tidak ada CHECK constraint di tabel `accounts`.

**QA-11 — Insufficient stock saat DO → 500, bukan 4xx.** Repro: DO qty melebihi on-hand → 500 `DELIVERY_CREATE_FAILED` (log: `insufficient stock on hand`). Penolakan bisnis yang benar tapi salah kelas error.

**QA-12 — `GET /forecast/cash-flow` → 500 schema drift.** Log: `column si.amount_due_cents does not exist (SQLSTATE 42703)` — query forecast tidak mengikuti rename kolom invoices (kini `receivable_cents`).

**QA-13 — `GET /production-jobs` → 500.** Log: `invalid input syntax for type date: ""` — parameter tanggal kosong pada list query tidak ditangani.

**QA-14 — `POST /dashboard/widgets` tanpa `config_json` → 500.** Log: `null value in column "config_json" ... violates not-null constraint`. Harusnya default `'{}'`.

**QA-15 — Validasi item menyesatkan & case-sensitive.** Check-constraint violation apa pun dilaporkan `"invalid field value (check abc_classification)"` meski yang salah kolom lain (mis. `costing_method:"FIFO"` uppercase ditolak karena DB minta lowercase `fifo`). User diarahkan ke kolom yang salah.

**QA-16 — Fixed asset create gagal (kolom `rate` NOT NULL).** Repro: POST fixed-assets dengan `depreciation_method:"straight_line"` + `useful_life_months` → 400 `null value in column "rate"`; API tidak menghitung/men-default-kan rate, raw SQLSTATE bocor.

**QA-17 — Env mismatch attachment tidak persisten.** `docker-compose.yml` menyetel `STORAGE_ROOT=/data/audit` (volume ter-mount), tetapi config membaca `ATTACHMENT_STORAGE_ROOT` default `/data/attachments` (tidak ter-mount) → lampiran hilang saat container recreate.

### LOW / INFO

- **QA-18 (LOW):** `/auth/logout` return 200 bahkan tanpa/garbage token (route di luar middleware auth) — semantik salah, jejak audit menyesatkan.
- **QA-19 (LOW):** SO dengan service item tanpa `sale_account_id` → 409 "order references a resource that does not exist" — pesan menyesatkan; validasi harusnya di create item ("service requires sale_account_id").

- **QA-22 (LOW):** Harness `TestMVPDatabaseInvariants` tidak re-runnable setelah failure: defer cleanup didaftarkan **setelah** eksekusi migrasi sukses, dan error cleanup diabaikan (`_, _ =`) → run berikutnya "relation already exists"; butuh DROP SCHEMA manual.
