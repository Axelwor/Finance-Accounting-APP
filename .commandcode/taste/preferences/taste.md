Confidence: 0.9
- Wants the product scope to cover the full operational accounting cycle, not just cash in/out bookkeeping: the complete sales order-to-cash flow (SQ → SO → DP → DO → INV → settlement), procurement flow (PR → PO → goods receipt → billing), inventory, simple production with job order costing (BOM, WIP, finished goods), and the complete fixed-asset lifecycle (registration, depreciation, revaluation, disposal) — each module mapped to its applicable PSAK standard. Confidence: 0.9
- Values accounting-domain accuracy in the technical specs: when told to "refine" a document, expects the assistant to self-audit and correct technical inaccuracies (e.g., wrong COA classification of advances/PPN, input VAT misposted as liability, improper revaluation/disposal journals), not just copy-edit. - Wants the document set kept internally consistent and versioned as it iterates: refining one spec (e.g., ACCOUNTING_ENGINE.md) should be reflected in related docs (e.g., PRD non-functional requirements) with version numbers bumped (v1.0 → v1.1); applies to each refined doc (DATA_MODEL.md was bumped v1.0 → v1.1 when refined). Confidence: 0.75
